# Claim transaction ownership

`wamn-10yt.22` makes the generated API own the transaction that contains a claim and its work. A claim records the request identity and the identities it creates. The owner approved `explicit_per_input` for generated creates and required ownership types without runtime policing.

`begin_claim(Transaction)` consumes the open transaction and returns `PendingClaim`. That type keeps the transaction private and exposes no commit method. Claim, replay, and work accessors take `&mut PendingClaim`. The custom finalizer consumes `PendingClaim` and returns `FinalizedClaim`, which exposes the result row and a consuming `commit()` method. For generated creates, `create` is the finalizing accessor. Receiving and the four WMS commands use this lifecycle, including their existing replay paths.

A custom command with a claim must declare `transaction: explicit_per_input`. Generation refuses an absent declaration and names the remedy, including `automatic_retry: false`. A custom finalizer must declare `fetch: one`, so finalization requires one returned row. Generated create contracts now declare `explicit_per_input`, and their claim, replay, and insert accessors share the owned transaction.
