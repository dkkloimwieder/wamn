## Standing rules

- A crate has one purpose. What it defines is not defined again anywhere else.
- Prefer to delete. No compatibility paths.
- Platform pieces do not live with client pieces. SQL is not scattered across the code.
- Be generous in what is accepted and conservative in what is sent.
- Checks that are developer verification belong in build or dev, not in apply or deploy.
- One implementation per job: `hyper` (no `reqwest`), `moka` for caches, SQLx for all SQL (U2, tab 34), `jsonwebtoken` 11.1.0 with EdDSA, `oauth2` 5.0.0, `pg_query` as the one SQL parser, `postgres-protocol` for quoting.
- TLS on every PostgreSQL connection (tab 78).
- Stored datetimes are UTC. Time zone settings serve printed numbers and cron (tabs 13, 30).
- Prefer WIT interfaces. Stay close to wasmCloud practice (tab 24).
- Project tasks live in one xtask crate plus a justfile. Keep the `kcl` binary (tabs 43, 44, 81).
- Local development runs on `kind` (tab 88).

## Needs a ruling

1. **Revocation rule.** The stated rule is "revocation is immediate, no cache". Tab 17 finding 10 keeps the token cache (moka, with a TTL). Reword the rule, or bound the TTL? (tabs 17, 88 R-01)
2. **Event run key.** At dep7 the key holds the stream sequence (`event_batch.rs`: `event:<sequence>:<source_event_id>`). A row published again after the 120 s duplicate window starts a second run. Proposal: key on the source row position.
3. **Event message id.** Tab 03 ruling 6: the log position alone. Tab 83 still describes `<project>_<env>:<lsn>`. Rows from one `COPY` may share an LSN (inference). Proposal: commit LSN plus row index. Depends on check 1. (tabs 03, 83)
4. **Runs pinned to a release no host serves** are never claimed or reaped. (found at `553511bbd`)
5. **`wamn_control` role** has full write on the authority tables of every org, with no row security. (found at `553511bbd`)
6. **Connection authority.** Who may create or change a connection: a platform operator or a project admin? R-08 B settled loopback only. (tabs 15, 16, 88)
7. **Sockets and guest memory.** When does count mode become refusing? (found at `553511bbd`)
8. **`signed_reads`.** Who produces it, if `wamn.k` cannot state it? (tab 80)
9. **Typed list reads.** Fixed statements per sort and direction, or one statement with the sort chosen at run time from the declared fields? (Architecture, rules row 3)
10. **Manifest vocabulary and naming rules** that refuse the build. Tab 26 covers reserved model names. (Architecture, rules row 4)
11. **Feature order.** Which feature gets its dependency review first: screens or sync?
12. **Privilege check on every connection.** Keep it, shrink it or drop it, now that one login generation remains? (tabs 09, 65; Architecture, rules row 7)

## Defects with no ruling needed

- **Test code in shipped binaries.** `tests/integration` turns on `test-util` and `ops` as normal dependencies, and the Dockerfile builds `wamn-gates` with `wamn-host` in one cargo call (inference on the binary). Tab 86 finding 2 A removes the source.
- **`feed.limit`** has no maximum on a composed base route. (found at `553511bbd`)
- **Lifecycle lock.** If the lock session ends, the verb goes on with no lock. `environment/lock.rs` is still at dep7; tabs 62–64 did not re-read it.
- **NATS authorization Secret** is changed by read, merge and apply, with no version check. (found at `553511bbd`)
- **Web front headers.** No CSP, `X-Content-Type-Options`, frame limit, HSTS or `Referrer-Policy`. (found at `553511bbd`; tab 58 moves the web front to its own crate)
- **Unused declarations** no review tab covers: the WIT world `runner-http-effect-plugin` and six unused root workspace dependencies. Default: delete.
