## Questions

1. I. Does “client base paths” cover the complete app mount? Recommend one prefix for app pages, assets, configuration, and API, with a canonical trailing slash at the mount.
2. I. What can a project or app be named? Recommend one URL-safe segment per name, a short list of reserved root segments, and the same project rule in Rust and SQL.
3. I. What are the public native paths and control addresses? Recommend mounted `api/files`, `api/flow`, and `api/health`; keep the current control routes and callback on the org origin.
4. I. What serves identity and the landing page on non-prod hosts? Recommend one root identity shell per public host. Use an eligible default if set, then show a chooser of eligible apps.
5. I. What does the active role mean after an app switch? Recommend resolving authorization for the destination project and environment on each request. Keep the existing org token.
6. I. How does the operator select prod, and where does control discovery move? Recommend an explicit provisioning choice stored in the registry, a Namespace label set from that committed choice, and metadata on the existing control HTTP Service.
